brnr
GitHub

A burner phone for your coding agents.

Run Claude Code or Codex from your editor as usual, then message it, watch it and answer its permission requests from any terminal. It keeps working after the editor closes.

brew install brnrhq/tap/brnr

Or build it with Cargo: cargo install --git https://github.com/brnrhq/brnr

How it works

Your editor still talks to the agent over ACP. brnr moves the agent into a host process that you can reach from outside.

editor ──stdio── brnr proxy ──socketpair── brnr host ──pipes── agent
                                              │
                                   control socket ── brnr send / watch / …
                                              │
                                           bridges (Slack, push, …)
brnr proxy
What the editor runs as its agent. It only relays bytes.
brnr host
Owns the agent for its whole life, in its own session. Killing the editor or the proxy can't take the agent with it unless you want it to.
Control commands
Talk to running hosts over a Unix socket that only you can open. Bridges use the same JSON-lines protocol to forward events to Slack, push notifications or anything else.

Use it from your editor

Set your editor's ACP agent command to brnr proxy and put the agent after --.

brnr proxy -- claude-agent-acp
brnr proxy -- codex-acp
brnr proxy --profile work          # agent and settings from a profile

When the editor goes away, on_disconnect decides what happens. With direct, the default, the agent stops the way it would if the editor had started it. With headless, it keeps running and brnr answers it in place of the editor.

Talk to it from outside

Target a host by its id, its --name or an ACP session id. A unique prefix is enough.

brnr list                          # running hosts and their sessions
brnr send demo "also update the changelog"
brnr send demo --after-turn "then run the tests"
brnr send demo --interrupt "stop, wrong branch"
brnr watch demo                    # every event and ACP message, live
brnr pending                       # permission requests waiting for an answer
brnr approve demo
brnr stop demo

Messages you send reach the agent as ordinary user messages, and the editor shows them as such.

Run it without an editor

Start a headless session and check in on it later.

brnr start --cwd ~/work/project --prompt "fix the failing tests" -- claude-agent-acp

The permissions setting in your profile handles permission requests. With ask, they wait for brnr approve, brnr deny or a bridge. Every session gets a transcript under ~/.brnr/projects, stored in the same folders as Claude Code's own transcripts.

# ~/.config/brnr/config.toml
[profiles.work]
agent = ["claude-agent-acp"]
on_disconnect = "headless"
permissions = "ask"                 # ask | auto-allow | auto-deny

Agents

brnr works with any ACP agent. It doesn't include one.

For Claude Code and Codex, install the ACP adapters with Homebrew (brew install brnrhq/tap/brnr-adapters, which compiles them on your machine) or from npm (claude-agent-acp, codex-acp). Either way, they run your own claude or codex.

brnr runs on macOS and Linux.
