brnr
GitHub

A burner phone for your coding agents.

Run Claude Code or Codex from your editor as usual, and watch it from any terminal. Or run it with no editor at all, message it and answer its approvals from anywhere, and pick up an editor's session after the editor closes.

brew install brnrhq/tap/brnr

Or build it with Cargo: cargo install --git https://github.com/brnrhq/brnr

How it works

Your editor still talks to the agent over ACP. brnr moves the agent into a process of its own that you can reach from outside.

editor ──stdio── brnr acp ──socketpairs── brnr process ──pipes── agent
                                             │
                                  control socket ── brnr prompt send / event watch / …
                                             │
                                          bridges (Slack, push, …)
brnr acp
What the editor runs as its agent. It only relays bytes.
The brnr process
Owns the agent for its whole life, out of the editor's process group. When the editor goes, it stops the agent the way the editor would have. brnr process list lists them.
Control commands
Talk to running sessions over a Unix socket that only you can open. Bridges use the same JSON-lines protocol to forward events to Slack, push notifications or anything else.

Use it from your editor

Set your editor's ACP agent command to brnr acp and put the agent after --.

brnr acp -- brnr-claude-adapter
brnr acp -- brnr-codex-adapter
brnr acp --profile work          # agent and settings from a profile

The editor and the agent talk as before. Watching the editor's sessions from outside always works; acting on them (sending, approving, changing the mode) is experimental, and enabled one action at a time in the profile.

When the editor goes away, the agent stops the way it would if the editor had started it. brnr session resume carries on with its session headless.

Talk to it from outside

Name a session by its id, as brnr session list shows it with the agent's title.

brnr session list                  # open sessions and ended ones; -- <agent>: the agent's too
brnr prompt send $s "also update the changelog"   # held while a turn runs
brnr prompt send $s --steer "and the tests too"   # into the running turn
brnr prompt send $s --interrupt "stop, wrong branch"
brnr event watch $s                # messages, tools, plan and approvals, live
brnr permission requests           # approvals waiting for an answer
brnr permission allow $s p1
brnr session close $s

Messages you send reach the agent as ordinary user messages, one turn at a time: brnr never sends a second prompt while a turn runs. In an editor's session, prompt send and permission allow work once its profile enables them.

Run it without an editor

Start a headless session and check in on it later.

brnr session new --cwd ~/work/project --prompt "fix the failing tests" -- brnr-claude-adapter

Approvals wait for brnr permission allow, reject or a bridge; how much the agent asks is its own mode (--mode). Every session gets a transcript under ~/.brnr/projects, in folders named like those of Claude Code's own transcripts.

# ~/.config/brnr/config.toml
[profiles.work]
agent = ["brnr-claude-adapter"]

[profiles.work.headless]            # for brnr session new and resume
stop_when_idle = 600                # close a session idle 10 minutes
mode = "acceptEdits"                # the agent's mode, before the first prompt

Agents

brnr works with any ACP agent. It doesn't include one.

For Claude Code and Codex, brnr uses the community's ACP adapters: claude-agent-acp by Zed Industries and contributors, and codex-acp by JetBrains. Install them from npm, or with Homebrew (brew install brnrhq/tap/brnr-claude-adapter or brnrhq/tap/brnr-codex-adapter), which compiles them on your machine into standalone executables that need no Node.js. Either way, they run your own claude or codex.

brnr runs on macOS and Linux.
