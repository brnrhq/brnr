brnr
GitHub

A burner phone for your coding agents.

Run Claude Code or Codex from your editor as usual, then message it, watch it and answer its approvals from any terminal. Or run it with no editor at all, and pick up an editor's session after it closes.

brew install brnrhq/tap/brnr

Or build it with Cargo: cargo install --git https://github.com/brnrhq/brnr

How it works

Your editor still talks to the agent over ACP. brnr moves the agent into a process of its own that you can reach from outside.

editor ──stdio── brnr acp ──socketpair── brnr process ──pipes── agent
                                            │
                                 control socket ── brnr send / watch / …
                                            │
                                         bridges (Slack, push, …)
brnr acp
What the editor runs as its agent. It only relays bytes.
The brnr process
Owns the agent for its whole life, out of the editor's process group. When the editor goes, it stops the agent the way the editor would have. brnr ps lists them.
Control commands
Talk to running sessions over a Unix socket that only you can open. Bridges use the same JSON-lines protocol to forward events to Slack, push notifications or anything else.

Use it from your editor

Set your editor's ACP agent command to brnr acp and put the agent after --.

brnr acp -- brnr-claude-adapter
brnr acp -- brnr-codex-adapter
brnr acp --profile work          # agent and settings from a profile

When the editor goes away, the agent stops the way it would if the editor had started it. brnr start --resume carries on with its session headless.

Talk to it from outside

Name a session by its id, as brnr list shows it with the agent's title.

brnr list                          # running sessions; --all: ended ones too
brnr send $s "also update the changelog"
brnr send $s --after-turn "then run the tests"
brnr send $s --interrupt "stop, wrong branch"
brnr watch $s                      # messages, tools, plan and approvals, live
brnr pending                       # approvals waiting for an answer
brnr approve $s p1
brnr close $s

Messages you send reach the agent as ordinary user messages, and the editor shows them as such.

Run it without an editor

Start a headless session and check in on it later.

brnr start --cwd ~/work/project --prompt "fix the failing tests" -- brnr-claude-adapter

The permissions setting in your profile handles approvals. With ask, they wait for brnr approve, brnr deny or a bridge. Every session gets a transcript under ~/.brnr/projects, stored in the same folders as Claude Code's own transcripts.

# ~/.config/brnr/config.toml
[profiles.work]
agent = ["brnr-claude-adapter"]
stop_when_idle = 600                # close a session idle 10 minutes
permissions = "ask"                 # ask | auto-allow | auto-deny

Agents

brnr works with any ACP agent. It doesn't include one.

For Claude Code and Codex, brnr uses the community's ACP adapters: claude-agent-acp by Zed Industries and contributors, and codex-acp by JetBrains. Install them from npm, or with Homebrew (brew install brnrhq/tap/brnr-claude-adapter or brnrhq/tap/brnr-codex-adapter), which compiles them on your machine into standalone executables that need no Node.js. Either way, they run your own claude or codex.

brnr runs on macOS and Linux.
